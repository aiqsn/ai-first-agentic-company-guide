Foundations

What agentic-AI-first means, how maturity progresses, and the path to get there

3

The shift: from AI as a tool people use to agents that run the work

Three differences from "using AI": work is redesigned, not augmented; agents have identity, tools and permissions; people move up the stack.

Becoming an Agentic-AI-First Organization
4
An agentic-AI-first organization designs work so agents plan, act and complete multi-step tasks by default, with people setting goals, approving consequential decisions and owning outcomes. Today people are the integration layer; in the agentic model agents are, and people set direction and judge results.

Autonomy rises as platform, controls and work redesign mature

Most organizations sit at Stage 1 or 2. The target is Stage 3 broadly and Stage 4 in core value streams.

Becoming an Agentic-AI-First Organization

Each step up needs platform capability, governance controls and redesigned work to move together. Promote a workflow only when its evaluations and incident record justify it.

Six steps, with work redesign as the step most programs skip

Start with high-volume, rules-rich, reversible workflows. Steps 3 to 6 repeat for each new value stream.

Becoming an Agentic-AI-First Organization
6
Good first candidates: claims intake, reconciliations, code maintenance, research synthesis. Avoid starting where a single agent error is costly or irreversible.

One trust layer governs every layer of the agent platform

Key points

  • Build one shared agent platform, not a platform per team
  • Five functional layers, from channels down to models
  • Every agent call passes through a single trust layer
  • Keep layers loosely coupled: swapping a model or MCP server should never mean rewriting an agent
Becoming an Agentic-AI-First Organization
7
Models and tools will change faster than workflows. The trust layer covers identity, policy, guardrails, sandboxing, tool supply-chain review, tracing, evaluations and cost controls.
02

Technical deep dive

The chain of enforcement points every agent action crosses

8

Every tool call passes a policy check and a gateway before it touches a system

The policy engine is the single choke point: an action that cannot be expressed as a policy decision cannot be governed or audited.

Becoming an Agentic-AI-First Organization
9
The trust layer is not one product. It is a chain: orchestrator, agent, policy engine, MCP gateway, sandboxed tool, output guardrail, back to the agent loop, with every step emitting an OpenTelemetry span.

Agents act on behalf of a user with a down-scoped, audience-bound token

Key points

  • One workload identity per agent, per environment (SPIFFE ID, attested by SPIRE)
  • Act on behalf of, never as: RFC 8693 token exchange names user (sub) and agent (act)
  • Lifetimes in minutes, bound to one audience
  • MCP servers reject tokens not issued for them and never pass tokens through
Becoming an Agentic-AI-First Organization
10
MCP authorization (spec 2026-07-28): servers are OAuth 2.1 resource servers publishing Protected Resource Metadata (RFC 9728); clients send the RFC 8707 resource parameter. The token claims shown are illustrative.

The MCP gateway runs five checks before any call reaches a tool server

Agents never connect to MCP servers directly. Treat tool descriptions and results as untrusted input, like web content.

Becoming an Agentic-AI-First Organization
11
Registry check with pinned digests, description diffing to catch rug pulls and tool poisoning, schema and limit checks, a policy decision per call, and redaction plus logging in both directions.

Policy changes ship like code: reviewed, tested, versioned and audited

One versioned policy file per workflow drives enforcement, approvals and audit. Engines such as OPA or Cedar evaluate it inline at the gateway.

Becoming an Agentic-AI-First Organization
12
An illustrative policy sets the workflow's agent identity, autonomy tier, pinned model, allowed and approval-required tools, limits such as payment ceilings and token TTL, and an egress allow-list.

Each task runs in a throwaway sandbox with no standing access

Ephemeral Firecracker microVMs or gVisor sandboxes, secrets injected per task by a broker, egress only through an allow-listed proxy.

Becoming an Agentic-AI-First Organization
13
No ambient credentials and nothing secret in the prompt or context window. Read-only base images; CPU, memory and wall-clock quotas; scratch disk wiped when the task ends.

Reads and writes to memory pass through separate, enforced paths

Retrieval enforces source access as the principal; memory writes are validated and attributed to prevent poisoning.

Becoming an Agentic-AI-First Organization
14
Separate short-lived task context from long-term memory. Partition memory per tenant, user and workflow. Apply retention limits and support erasure requests.

Delegation narrows at every hop

Key points

  • MCP for agent-to-tool, A2A for agent-to-agent
  • A2A is hosted by the Linux Foundation, with 150+ supporting organizations in its first year
  • No transitive trust: each hop re-authenticates
  • Delegated scopes only shrink, and delegation depth is capped

No change reaches production without passing four evaluation stages

Re-run evals on every change to prompts, tools, policies or models. Promotion to a higher tier needs a pass-rate threshold plus a clean incident window.

One trace shows every step, decision and approval in a task

Instrument with OpenTelemetry GenAI conventions (still at Development stability: pin the version) and add custom audit attributes.

Governance, people and the first 90 days

How autonomy is earned, how the organization is shaped, and how to start

18

Autonomy is earned tier by tier, per workflow

Set the tier per workflow, not per agent: the same agent can run at Tier 4 for invoice matching and Tier 2 for vendor payments.

Becoming an Agentic-AI-First Organization
19
Promote only when evaluation results and incident history justify it; demote on any serious incident.

Treat every agent as a privileged workload that can be manipulated through its inputs

IdentityOwn workload identity per agent (for example SPIFFE/SPIRE), never a shared service account or borrowed human credential

Prompt injection defenseUntrusted content treated as data; guardrail models on inputs and outputs; no permission escalation from content

What carries over in each case: process knowledge, domain judgment, systems and test design, infrastructure and identity skills, control frameworks, coaching.

People move from doing the work, to supervising it, to designing it

  • Train every employee to delegate to agents: clear goals, reviewing output, knowing when to escalate
  • Rewrite job descriptions and performance goals around outcomes supervised, not tasks performed
  • Each executive sponsors at least one agentic workflow

Fund reskilling for every step, and make supervision a real job with clear decision rights, not a rubber stamp.

Becoming an Agentic-AI-First Organization

Be explicit about workforce impact and reskilling paths: uncertainty kills adoption faster than any technical issue.

Measure outcomes, not usage, and avoid the six common traps

Metrics

Pitfalls

  • Pilot sprawl: many demos, none in production
  • Automating a broken process instead of redesigning it
  • Granting agents broad human credentials
  • Onboarding MCP servers without supply-chain review
  • Skipping evaluation
  • Treating it as an IT project, not an operating-model change

Measure outcomes at the workflow level. Pitfalls are the most common reasons agentic programs stall or get canceled.

Ninety days, three phases, each ending in a go or no-go gate

Treat each gate as a real decision: if its criteria are not met, extend the phase rather than starting the next one.
